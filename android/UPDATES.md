# Android in-app updates

Android 0.1.1 adds startup checks and the existing clickable update notification, using the saved Update notifications, Notification sound and sound-volume preferences. General > Check for updates also works when notifications are disabled.

Only this repository's `android-vMAJOR.MINOR.PATCH` releases are considered, including Android preview prereleases. Windows releases are ignored. Publish the ARM64 asset as `KAYLiveSport-android-arm64-debug.apk`; GitHub must provide its SHA-256 asset digest. Download and installation both verify the exact release, size and digest. Downloads stay in the app-private cache and are shared through a narrowly scoped FileProvider.

Install update opens Android's installer after checking the APK package ID, newer version code and identical signing certificate. If installation permission is missing, the button opens Android's per-app permission screen. The user must grant permission, return to KAY LIVE SPORT and tap Install update again. The user confirms Update in Android, then taps Open after installation. The app does not silently install, automatically grant permission, uninstall itself or clear settings.

Keep package ID `com.kaylivesport.mobile` and the existing signing key for every update. The current preview uses this machine's existing Android debug keystore; preserve that key privately. A different key is rejected rather than suggesting uninstall. Bump both Cargo and Tauri Android versions before each new release so versionCode increases. Android 0.1.0 requires a one-time manual install of 0.1.1; future upgrades can use the new flow.

Validation: ARM64 APK built; Android signature and 16 KB alignment verified; Rust release-selection/checksum tests, shared update UI tests (notification, Android install-permission and installer-return states) and mobile portrait/landscape checks passed. On the connected Redmi, in-place install retained saved preferences; live GitHub check returned Android 0.1.1/up_to_date and the native installer bridge returned installAllowed=false. End-to-end test on 2026-10-19: temporarily installed a same-source updater-capable 0.1.0 baseline without clearing app data, received the startup notification, downloaded the published android-v0.1.1 APK from GitHub inside the app, and verified its SHA-256 against the published artifact. The user granted Android installation permission and confirmed the package installer update. The installed package returned to version 0.1.1/code 1001; all six existing localStorage entries matched the immediate pre-install snapshot exactly, and the app reported up_to_date with no repeat update notification. This baseline is a local test build, not the original published 0.1.0. No test APK was published.

APK downloads now retain an app-private partial file on Cancel or a network interruption. Download update resumes with an HTTP Range request after confirming the release URL, SHA-256 and size still match the saved sidecar. A full HTTP 200 response safely restarts from zero; invalid partial response ranges are rejected. Completed files are verified before the install button is enabled. Local HTTP tests cover interruption/resume, servers ignoring Range and changed assets.
